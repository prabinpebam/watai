# Memory research evidence register

**Accessed: 2026-09-10.** This is a fresh, bounded primary-source review, not a claim to exhaust the latest literature. Twelve substantive primary sources were read; M13 is supplementary secondary research and is **not** counted as primary evidence. Versions matter: ACE was checked against its March 2026 revision, A-Mem against v11, and LongMemEval against v2. Live vendor documentation can change after access.

HTML was retrieved with `web_fetch`; raw HTML and a read-only Python standard-library parser were used when simplification exposed only introductions or navigation. No Watai source, credentials, user conversations, or production data were sent to these sites. Bibliographic dates below are visible publication/version metadata, not inferred from an arXiv identifier. “No date exposed” means no reliable publication/update date was visible in the consulted material.

**Category map:** C07 = memory quality; C08 = memory control/governance. Comparisons support design decisions, not transfers of benchmark scores to Watai. Paper results are experimental claims under their own datasets, models, prompts, costs, and scoring protocols.

## Critical synthesis for the scored categories

### C07 — Memory quality

M01–M04 jointly favor evaluation of capture, reconciliation, retrieval, and answer reading as separate failure points. They do not establish one winning architecture. The most direct current-code improvement is replacing newest-20 consolidation context with relevant evidence candidates and retaining temporal/subject qualifiers; none requires Graphiti.

M06/M07 make tiered memory understandable, while M08 offers a more agentic alternative. Watai should not confuse grouped prose with a stable identity model or assume more autonomy fixes attribution. M09 and the 2026 revision of M12 give an important tension: preserve useful detail over time, but test what should enter each prompt. A versioned evidence store plus small selected profile resolves that tension better than either “throw away all detail” or “inject everything.”

### C08 — Memory control and governance

M10/M11 provide concrete, current product examples of independent read/write/history modes and honest deletion/retention explanations. M07 demonstrates that a system can retain information beyond context eviction, highlighting why user-visible presence is not the same as persistence. M04/M05’s provenance/history is valuable for corrections but explicitly different from erasure. M08/M12 multiply derived representations: deletion lineage must improve before adding these techniques.

Therefore the governance recommendation is a locally enforceable permission-and-deletion contract, not imitation of another vendor’s backend or retention period. No cited research proves that Watai honors its controls; only code-path tests and eventual operational evidence can do so.

## Retrieval limitations and unsuccessful attempts

- arXiv abstract simplification sometimes returned only a title; full HTML/raw abstract metadata was fetched before using those entries.
- `https://github.com/zep-ai/graphiti` and the old Letta `/concepts/memory/` URL returned 404. Correct current locations above were retrieved.
- A supplementary direct Python request to OpenAI’s FAQ did not expose usable article text. The report relies on the successful `web_fetch` article sections, not that failed parser result.
- No exhaustive September 2026 paper search, subscription-only material, full PDF review, provider experiment, or independent reproduction was performed. The newest **verified revision used here** is ACE v3, March 2026; this does not mean no newer relevant work exists.
