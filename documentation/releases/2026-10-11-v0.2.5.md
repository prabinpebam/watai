# Watai 0.2.5: Node.js 24 API Runtime

Status: production API runtime switched to Node 24 and verified on the actual workers,
including a real chat-run completion on Node 24.
This closes the runtime drift tracked by H05 (`evidence/h05-node24-compatibility.json`):
IaC and `api/package.json` already declare Node 24. It is a Continuous Production
Milestone, not a DoD closure receipt (0 of 52 findings closed; H01 `BLOCKED_SAFE`).

## Scope

`functionAppConfig.runtime.version` 20 → 24 through
`az functionapp runtime config set --runtime-version 24`. The deployed code package is
the unchanged v0.2.4 package (SHA-256
`b06f7e33b51cdb47795cfc798d0a6f6e5e81b849b2f4416e1d9a44315918bd9f`, marker

## Follow-Up: Image Queue Declared

Production never had the `image-jobs` queue: `QueueImageStarter` creates it lazily on
the first Image Studio job, and Image Studio had never been used (0 image records).
The `imageWorker` queue trigger therefore polled a missing queue, producing about 670
"Error querying for queue scale status" warnings per week. The empty queue was created
at `2026-10-11T07:24:05Z` (`IMAGE_QUEUE` unset, so the worker uses `image-jobs`; 0
messages). `infra/main.bicep` now declares the run/image/memory queues as `stage.bicep`
already did; it was compiled, not applied. Rollback: delete `image-jobs` only while empty.
